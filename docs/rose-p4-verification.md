## Production and limitations

Database migration and `rose-event`/`rose-chat` updates are live, shared by preview and public site. The website was not published; P4 frontend, dashboard and privacy copy require publication. The clean collection period starts at instrumentation rollout but public client instrumentation begins only after publication. Positive write/readback metrics were intentionally NOT_TESTED to avoid inserting synthetic rows into the production event table; the authenticated dashboard reads actual empty aggregates. Distributed spoofed-origin/session-rotation spam is not fully prevented. Legal consent exemption, provider log retention, second-tab behavior, screen-reader audit and regenerated public pre-renders are unverified. No external provider, feedback widget, automatic learning or general traffic dashboard was added.

Recommended next cycle: address directness and booking-link duplication as one bounded conversational change, then rerun recruiter, generic method and explicit-contact scenarios before making a full quality claim. Do not optimize engagement rates while the clean baseline is empty.
